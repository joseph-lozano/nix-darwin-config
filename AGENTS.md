# Repository Guidance

## Purpose

This repository provisions Joseph Lozano's personal Apple-silicon Mac with Homebrew Bundle, mise, GNU Stow, and direct shell scripts. It is not intended to be reusable by other users. Prefer fixed, readable configuration over parameters, host matrices, wrappers, or framework abstractions for a single machine.

The identity is intentionally fixed:

- user: `joseph`
- home: `/Users/joseph`
- platform: native Apple-silicon macOS (`arm64`)
- checkout: `/Users/joseph/nix-darwin-config`

The workflow is agent-first: Cursor is the primary coding editor, bare Vim handles terminal/Git editing, Amp, Pi, and Codex are coding agents, ChatGPT is the desktop AI client, and Herdr is the terminal multiplexer. Do not add Neovim, Vim plugins/configuration, other editors, Ollama, or Claude tooling unless explicitly requested.

## Layout and Ownership

- `Brewfile` owns conventional formulae, casks, the IntoneMono Nerd Font, Herdr, OrbStack, and Docker Sandboxes.
- `install.sh` owns the idempotent install-or-update entry point. It validates the machine, converges a clean `main` checkout, installs Homebrew, and delegates to the scripts.
- `scripts/dotfiles.sh` links only the static packages under `stow/`.
- `scripts/agents.sh` owns official agent installers, mise's Node/Aube setup, public skills/Pi config synchronization, and surgical agent integrations.
- `scripts/macos.sh` owns macOS defaults, firewall/update settings, Rosetta, Touch ID for sudo, keyboard mappings, symbolic hotkeys, and Dock contents.
- `scripts/verify.sh` checks the realized Mac after setup.
- `stow/` contains static Git, SSH, Zsh, Powerlevel10k, and Ghostty configuration.
- `stow/zsh/.p10k.zsh` was generated by the Powerlevel10k wizard. Prefer `p10k configure` over hand-editing it unless a targeted change is requested.

Keep behavior in its existing owner. Do not add a module or helper for a small one-off setting.

## Critical Ownership Boundaries

- Amp uses its official installer so `amp update` remains supported. Do not add the Homebrew, npm, or Nix Amp package.
- Codex uses its official installer. `~/.codex/config.toml` and `hooks.json` are writable shared application config; never Stow-link or replace the whole Codex directory.
- mise uses its official installer and owns Node LTS and Aube. Node is the only global runtime. Project-specific runtimes belong in each project's mise config.
- Aube activation intentionally adds shims for Node and npm-family commands. Pi also has an explicit `npmCommand` using `mise exec node@lts -- npm`; preserve both layers.
- Pi's CLI is installed with npm under mise's Node. `~/.pi/agent/settings.json`, credentials, sessions, package stores, and caches remain writable. Link only selected static files from `joseph-lozano/pi`; never run that repository's whole-directory `setup.sh` here.
- `joseph-lozano/skills` is flattened into `~/.agents/skills`. Herdr and Plannotator add their own explicitly managed skill directories beside it.
- Plannotator uses its minimal official installer because the full installer creates Claude-specific files. This repository separately installs only Amp, Codex, Pi, and shared-skill integrations.
- Herdr owns its generated Pi/Codex integration files and mutable session/runtime state. It detects Amp without an installable Amp integration.
- Setapp owns CleanShot X, TablePlus, In Your Face, and other subscription Favorites. Do not add standalone Homebrew copies that bypass Setapp licensing/updates.
- Application data, sign-ins, secrets, caches, sessions, trust, browser profiles, and GUI preferences are never Stow-managed.

## Change Policy

- The owner wants modernization suggestions, but propose and receive approval before changing package/cask selections, macOS defaults, ownership boundaries, update behavior, or interactive app choices unless the current request explicitly approves that exact change.
- Never add `brew bundle cleanup` or another automatic removal step without explicit approval. Undeclared Homebrew software is intentionally preserved.
- Do not reintroduce Nix, nix-darwin, Home Manager, Ansible, Chezmoi, or Git submodules without explicit approval.
- Do not add secrets, private keys, API tokens, credentials, or machine-generated application state. The Git signing key in `stow/git/.gitconfig` is a public key.
- Preserve unrelated personal preferences even when a conventional alternative exists.
- Never run the full installer or apply macOS settings from a non-Mac environment. On the user's Mac, running `install.sh` changes system/shared state and should be done only when explicitly requested.
- Do not push without explicit approval.

## Install and Update Contract

The README's one-line command must remain valid for both a fresh Mac and later updates. Preserve these properties:

- fail unless the account is `joseph`, home is `/Users/joseph`, and the shell is native `arm64` macOS;
- install Apple Command Line Tools and Homebrew when absent;
- clone when absent, otherwise require a clean `main` checkout and fast-forward only;
- upgrade declared Homebrew software without destructive cleanup;
- use supported upstream installers/update paths rather than competing package owners;
- leave mutable application config writable;
- be safe to rerun; and
- finish with `scripts/verify.sh` and actionable failures.

## Validation

For every script or config change, run:

```sh
sh -n install.sh
bash -n scripts/*.sh
shellcheck install.sh scripts/*.sh
git diff --check
```

Inspect `git diff` for ownership drift, destructive commands, accidental secrets, and stale Nix references. If Homebrew is available, also validate the Brewfile with `brew bundle check --file=./Brewfile` or Homebrew's parser.

Actual Homebrew casks, macOS defaults, PAM, Rosetta, Dock state, symbolic hotkeys, GUI permissions, and app sign-ins can only be verified on the Apple-silicon Mac. In Linux or an orb, report that limitation rather than claiming Mac-side validation passed.
