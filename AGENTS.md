# Repository Guidance

## Purpose

This is Joseph Lozano's personal nix-darwin configuration for provisioning Apple-silicon Macs. It is not intended to be reusable by other users. Prefer direct, readable configuration over parameters, host matrices, helper modules, or other abstractions that only make a single-user setup more generic.

The coding workflow is agent-first: Cursor is the primary coding editor, bare Vim handles terminal and Git editing, Pi and Codex are the terminal coding agents, ChatGPT is the desktop AI client, and Herdr is the terminal multiplexer. Do not add Vim plugins or configuration, Neovim or other editors, or Claude tooling unless explicitly requested.

The current identity is intentionally fixed:

- User: `joseph`
- Home: `/Users/joseph`
- Darwin configuration: `Josephs-MacBook-Pro`
- Platform: `aarch64-darwin`

Do not rename or parameterize these values unless explicitly requested.

## Layout and Ownership

- `flake.nix` pins inputs and assembles nix-darwin, Home Manager, and nix-homebrew. It also exposes the public shared-skills and Pi configuration inputs to Home Manager.
- `system.nix` owns macOS defaults, keyboard behavior, Touch ID, and `system.stateVersion`.
- `homebrew.nix` owns Homebrew formulae/casks, the IntoneMono Nerd Font cask, and activation cleanup.
- `home.nix` owns Home Manager packages, environment variables, managed files, shared skill installation, Pi configuration installation, and top-level program configuration.
- `install.sh` owns the idempotent install-or-update flow exposed by the README's one-line installer.
- `home/git.nix` owns Git identity, signing, aliases, and defaults.
- `home/zsh.nix` owns additional Zsh history and initialization. Zsh is configured in both this file and `home.nix`; inspect both before changing shell behavior.
- `home/p10k.zsh` is generated by the Powerlevel10k wizard. Prefer regenerating it with `p10k configure` over hand-editing it unless a targeted manual edit is requested.

Keep behavior in the file that already owns it. Do not add a new module for a small one-off setting.

## Change Policy

- The owner wants modernization suggestions, but configuration modernization must be proposed and approved before implementation unless the user's current request explicitly approves that exact change.
- Ask before changing package/cask selections, macOS defaults, the Nix ownership model, Homebrew cleanup/tap behavior, input refs, or the lock file.
- Treat `flake.lock` updates as a separate change. Never update it incidentally while formatting, evaluating, or fixing unrelated configuration.
- Never bump `system.stateVersion` or `home.stateVersion` as part of a routine upgrade. They preserve compatibility and should change only after reviewing the relevant migration notes and receiving explicit approval.
- `homebrew.onActivation.cleanup = "uninstall"` removes unmanaged packages during activation. Call out that impact before changing or activating Homebrew configuration.
- Never run `darwin-rebuild switch` or otherwise activate the system without explicit approval. Evaluation and non-activating builds are safe defaults.
- Do not add secrets, private keys, access tokens, or machine-specific credentials. The Git signing key already present is a public key.
- Preserve unrelated personal preferences even when a more conventional setting exists.

## Validation

Run checks without modifying the lock file:

```sh
nix fmt
nix flake check --no-update-lock-file --show-trace
nix build --no-link --no-update-lock-file '.#darwinConfigurations.Josephs-MacBook-Pro.system'
```

On a configured Mac, this is an equivalent non-activating nix-darwin check:

```sh
darwin-rebuild build --flake '.#Josephs-MacBook-Pro'
```

Only after explicit approval, activate with:

```sh
sudo darwin-rebuild switch --flake '.#Josephs-MacBook-Pro'
```

This repository has no automated tests beyond its flake evaluation and system build. Use the declared formatter for Nix files, avoid unrelated reformatting, and always run `git diff --check`. If Nix is unavailable or a Darwin build cannot run in the current environment, report that limitation rather than claiming validation passed.

## Upgrade Notes

The inputs follow unstable/master branches and were last refreshed in August 2026. Before updating them again, review current nix-darwin, Home Manager, and nix-homebrew release notes together. Preserve these deliberate integration choices:

- Determinate Nix owns the Nix installation and daemon, so nix-darwin has `nix.enable = false`. Do not add nix-darwin-managed `nix.*` settings unless the ownership model is intentionally changed.
- `system.primaryUser = "joseph"` ensures Homebrew and user-scoped macOS defaults activate for the intended account.
- `system.stateVersion = 4` and `home.stateVersion = "24.05"` remain at their original compatibility versions.
- Setapp itself is installed through Homebrew, while subscription apps such as CleanShot X, TablePlus, and In Your Face are installed from the owner's Setapp Favorites. Do not add standalone Homebrew or App Store copies of those apps unless explicitly requested; they would bypass Setapp licensing and updates.
- Home Manager activates mise in Zsh and configures Node LTS and Aube globally. Aube's Zsh activation intentionally routes Node and npm-family package-manager commands through its shims. Other runtimes belong in each project's `mise.toml`; do not add another global runtime unless explicitly requested.
- Homebrew installs `font-intone-mono-nerd-font`, and Ghostty selects `IntoneMono Nerd Font Mono`. Do not add the duplicate Nixpkgs font package.
- Home Manager flattens the public `joseph-lozano/skills` input into `~/.agents/skills`. The public `joseph-lozano/pi` input supplies static files under `~/.pi/agent`, while `settings.json`, credentials, sessions, package state, and caches remain writable local state. Pi's wrapper privately adds Nixpkgs Node/npm to its child-process path for package installation; interactive Node remains mise-managed. Herdr owns and installs its Pi integration extension.
- Plannotator is pinned as a release source and Apple-silicon binary in the flake/Home Manager configuration. Home Manager owns its Amp plugin, Codex skills and hook, and Pi package declaration; Plannotator owns its writable local review data. Home Manager seeds `~/.codex/config.toml` only when missing because Codex persists project trust in that writable file.
- Rosetta 2 installation, the macOS application firewall with stealth mode, and automatic system and security updates are deliberate fresh-Mac defaults.

The following preference decisions remain open; propose them rather than changing them opportunistically:

- nix-homebrew's declarative taps and nix-darwin's `homebrew.taps` should be kept aligned if tap management is modernized.
